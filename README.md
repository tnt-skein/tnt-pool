# tnt-pool

Пул соединений для Tarantool: держит несколько открытых соединений
с чужой службой и раздаёт их тем, кто просит. Протоколов не знает —
как открыть, закрыть, проверить живость и сбросить соединение перед
возвратом, ему говорит тот, кто им пользуется.

```lua
local pool = require('tnt.pool')

local p = pool.new({
    open = function(left) return client.connect({ timeout = left }) end,   -- left — остаток срока take
    close = function(c) c:close() end,
    size = 8,            -- больше восьми одновременно не открывать
    wait_timeout = 5,    -- дольше пяти секунд не ждать своей очереди
})

-- Взять, сделать, вернуть — в любом исходе; упавшее тело соединение выбрасывает.
local rows, err = p:with(function(c)
    return c:execute('select 1')
end)
```

Зависимости: `tnt-must` (проверка настроек), `tnt-clock` (монотонные
часы), `tnt-log` (журнал), `tnt-loop` (такт уборки) и `tnt-external`
(подмена часов и условной переменной в проверках).

## Зачем

Соединение с базой открывается долго, а запрос по нему занимает
миллисекунду: открывать его на каждый запрос значит платить за вход
всегда, держать одно на всех — выстроить файберы в очередь за ним.
Пул в двадцать строк ошибается безобидно на вид, пока не придёт
нагрузка: ожидание крутит цикл, ждут без срока, упавшая служба получает
шторм переподключений, соединение после ошибки возвращается в пул,
а невозвращённое не видно никому. Пакет делает шесть вещей:

- **Честная очередь на условных переменных.** Ждущий снимается
  с планировщика до побудки; соединение достаётся первому в очереди.
- **Срок ожидания обязателен**, и `open` получает остаток этого срока
  аргументом: вход не продлевает `take` дольше его срока.
- **Пауза после отказа открытия растёт вдвое**, от 0,5 с до 30 с;
  взявший ждёт свой срок и получает внутри него несколько попыток.
  Отказ с `retriable = false` отдаётся сразу.
- **Соединение, на котором тело `with` упало, выбрасывается**, а `reset`
  не пускает в пул соединение с открытой транзакцией.
- **Утечки называются в журнале**: удержанное дольше `leak_timeout`
  находит уборка.
- **Состояние видно**: `stats` — мгновенные показатели и накопленные
  счётчики.

Для `net.box` пул не нужен: одно его соединение обслуживает сколько
угодно одновременных запросов, а предел на них стоит на сервере и общий
на все соединения.

## Установка

```sh
tt rocks install tnt-pool --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-pool.git
cd tnt-pool && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `pool.new(opts)` | заводит пул; настройки проверены сразу, соединения не открыты |
| `:take(timeout)` | берёт соединение; ждёт не дольше `timeout`, по умолчанию `wait_timeout`; отказ — `nil, err` |
| `:give(conn)` | возвращает; `reset` решает, лечь ли ему в свободные |
| `:drop(conn)` | выбрасывает негодное: закрывает и забывает |
| `:with(fn, timeout)` | берёт, зовёт `fn(conn)`, возвращает в любом исходе; упавшее тело — `drop` |
| `:sweep()` | закрывает истёкшие свободные, называет утечки |
| `:stats()` | мгновенные показатели и накопленные счётчики |
| `:close()` | закрывает пул; занятые закроются по возврату |
| `pool.configure(opts)`, `pool.default()` | общий пул процесса; заводится при первом обращении |

Настройки: `open` (обязательна), `close`, `alive`, `reset`, `size` (8),
`wait_timeout` (5), `idle_timeout` (60), `max_lifetime` (1800),
`open_cooldown` (0,5), `leak_timeout` (300), `sweep_interval` (5), `name`.
Незнакомый ключ и негодное значение — исключение в `pool.new`: опечатка
в имени иначе молча оставила бы умолчание.

Отказ по сроку называет причину — нехватку мест или отказ службы:

```text
соединение не получено за 5 с: все 8 заняты
соединение не получено за 5 с: открыть соединение не удалось: служба не отвечает
```

`alive` и `reset` работают без сети и без срока: сетевая проверка
удвоила бы обращения к службе, а на молчащем сервере не дала бы `take`
уйти в свой срок. Соединение, закрытое чужой стороной молча, обнаружит
первый запрос — отказом.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (139 проверок,
418 мутантов в четырёх модулях). Сроки, паузы и уборка проверяются
на часах, которые двигает сама проверка; очередь, закрытие посреди
ожидания и медленное открытие — на настоящих файберах.
