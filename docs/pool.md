# Пул соединений

`tnt-pool` держит несколько открытых соединений с чужой службой и раздаёт
их тем, кто просит: берут, работают, возвращают. Протоколов он не знает —
как открыть соединение, закрыть, проверить живость и сбросить перед
возвратом, ему говорит тот, кто им пользуется.

```lua
local pool = require('tnt.pool')

local p = pool.new({ open = connect, close = function(c) c:close() end, size = 8 })
local rows, err = p:with(function(c) return c:execute('select 1') end)   -- взять, сделать, вернуть в любом исходе
```

Нужен он там, где соединение обслуживает один запрос за раз: у роков
`pg` и `mysql` второй файбер на том же соединении ждёт первого, у SMTP
и сокета очереди — то же. Соединения `net.box` в него не кладут —
почему, сказано в разделе «Что пулить не надо».

Зависимости: `tnt-must` (проверка настроек), `tnt-clock` (монотонные
часы), `tnt-log` (журнал), `tnt-loop` (такт уборки) и `tnt-external`
(подмена часов и условной переменной в проверках). Остальное встроено
в Tarantool — `fiber`.

## Зачем пакет

Соединение с базой открывается долго: рукопожатие, вход, согласование
кодировок — десятки миллисекунд там, где сам запрос занимает одну.
Открывать его на каждый запрос значит платить эту цену всегда; держать
одно на всех значит выстроить файберы в очередь за ним. Между этими
крайностями и живёт пул: несколько соединений, которые берут, возвращают
и переоткрывают по мере надобности.

Написать пул в двадцать строк нетрудно, и ошибки такого пула выглядят
безобидно, пока не придёт нагрузка:

- **ожидание крутит цикл** — «не освободилось ли?» раз в миллисекунду
  занимает поток планировщика ровно тем, что ничего не делает, а
  соединение достаётся тому, кого планировщик поднял раньше, а не тому,
  кто дольше ждёт;
- **ожидание без срока** — файбер, ждущий соединения вечно, не ждёт
  никого: его не разбудит ни отказ службы, ни закрытие пула, и заметить
  его можно только по тому, что запрос не ответил никогда;
- **отказ службы превращается в шторм** — сто файберов, каждый со своей
  попыткой войти, мешают упавшей службе подняться; а отказ по первой же
  неудаче роняет все запросы из-за службы, моргнувшей на полсекунды;
- **соединение после ошибки возвращается в пул** — посреди транзакции
  или с недочитанным ответом, и следующий взявший получает его вместе
  с чужой бедой;
- **невозвращённое соединение не видно** — пул считает его занятым,
  запросов оно не делает, и однажды пул перестаёт выдавать что-либо.

Пакет делает для этого шесть вещей:

- **Честная очередь на условных переменных.** Ждущий снимается
  с планировщика до побудки, у каждого своя переменная, соединение
  достаётся первому в очереди.
- **Срок ожидания обязателен**, и `open` получает остаток этого срока
  аргументом: вход не продлевает `take` дольше его срока.
- **Пауза после отказа открытия растёт вдвое** с каждым отказом подряд,
  от 0,5 с до 30 с; взявший ждёт свой срок и получает внутри него
  несколько попыток. Отказ, который время не лечит, отдаётся сразу.
- **Соединение, на котором тело `with` упало, выбрасывается**, а сброс
  `reset` не пускает в пул соединение с открытой транзакцией.
- **Утечки называются в журнале**: соединение, удержанное дольше
  `leak_timeout`, находит уборка.
- **Состояние видно**: `stats` отдаёт и мгновенные показатели,
  и накопленные счётчики.

## Как пользоваться

### Завести пул и взять соединение: `new`, `with`

Пример — на роке `pg` 2.0.2 и PostgreSQL 16, проверен запуском.
Комментарии в нём — о том, на чём спотыкается пример, написанный
по памяти.

```lua
local pg = require('pg')
local pool = require('tnt.pool')

-- Значение строки соединения libpq: в кавычках, `\` и `'` экранированы.
-- Ключи `pg.connect({ host = …, password = … })` рок вставляет в ту же
-- строку как есть: пароль с кавычкой ломает вход, и обрывок пароля уходит
-- в текст отказа, а с ним — в журнал пула и в `last_open_error`.
local function libpq_value(value)
    return "'" .. (tostring(value):gsub('\\', '\\\\'):gsub("'", "\\'")) .. "'"
end

-- Куда и под кем входить — из настроек приложения:
-- { host = …, port = …, user = …, password = …, name = … }.
local db = settings.postgres

-- Строку `pg.connect(dsn)` рок не читает вовсе и молча идёт в локальный
-- сокет по умолчанию; строка соединения — ключ `conn_string`.
local conn_string = table.concat({
    'host=' .. libpq_value(db.host),
    'port=' .. libpq_value(db.port),
    'user=' .. libpq_value(db.user),
    'password=' .. libpq_value(db.password),
    'dbname=' .. libpq_value(db.name),
}, ' ')

local p = pool.new({
    -- Срока входа у рока нет, и остаток срока `take`, который `open`
    -- получает аргументом, ему не передать: вход к молчащему серверу продлит
    -- `take` на всё время молчания (раздел «Срок входа»).
    open = function()
        return pg.connect({ conn_string = conn_string })
    end,

    -- `close` рока на оборванном соединении бросает и сокет не закрывает.
    -- Тогда его закрывает объект драйвера под ним: иначе сокет ждал бы
    -- сборки мусора.
    close = function(c)
        if not pcall(c.close, c) then
            c.conn:close()
        end
    end,

    -- Живость — без сети (раздел «Проверка живости»). `active()` бросает,
    -- только когда рок сам пометил соединение негодным, а иначе отвечает,
    -- открыта ли транзакция: важен не ответ, а то, что он был.
    alive = function(c)
        return (pcall(c.active, c))
    end,

    -- Соединение с открытой транзакцией в пул не вернуть: следующий
    -- взявший зафиксировал бы чужую работу. `active()` у `pg` отвечает
    -- без сети, открыта ли транзакция.
    reset = function(c) return not c:active() end,

    size = 8,            -- больше восьми одновременно не открывать
    idle_timeout = 60,   -- простоявшее минуту закрыть
    wait_timeout = 5,    -- дольше пяти секунд не ждать своей очереди
})

-- Взять, выполнить, вернуть — в любом исходе.
local rows, err = p:with(function(c)
    -- Параметр — знак `$1` и аргумент после текста. `?` у `pg` —
    -- синтаксическая ошибка, а таблица `{ id }` вместо аргумента уходит NULL,
    -- и выборка молча пуста. Число рок передаёт типом numeric: без `::int`
    -- сравнение шло бы в numeric, мимо индекса по `id`.
    local sets = c:execute('select id, name from customers where id = $1::int', id)

    -- `execute` отдаёт наборы строк, по одному на оператор.
    return sets[1]
end)
```

`rows` — массив записей по именам столбцов: `{ { id = 1, name = 'Анна' } }`,
пустой, если записи нет.

Ошибку SQL рок не возвращает, а бросает, и `with` её ловит: соединение
выбрасывает, отказ отдаёт строкой вторым значением. Выброшено будет и
соединение, которому ошибка не повредила: нарушенная уникальность стоит
нового входа. Поэтому клиент базы поверх пула зовёт не `with`, а `take`,
`give` и `drop` сам и по месту отказа решает, вернуть соединение или
выбросить. Пример выше показывает пул, а не то, как ходить в базу.

Всё, что вернуло тело, `with` отдаёт как есть, сколько бы значений ни
было; отказ тела — `return nil, err` — поломкой не считается,
и соединение возвращается в пул (раздел «Сброс перед возвратом»).
Не взяв соединения, `with` тело не зовёт и отдаёт отказ `take`.

Соединения открываются по требованию, а не при заведении пула: пул,
открывший восемь соединений при старте узла, платит за них в тот миг,
когда узел и так занят подъёмом, — и платит зря, если до них так и не
дойдёт дело.

### Взять вручную: `take`, `give`, `drop`

`with` — основной способ. Ручной длиннее и требует дисциплины:

```lua
local c, err = p:take()

if c == nil then
    return nil, err
end

-- Рок отказывает исключением. Не пойманное, оно унесло бы соединение
-- с собой: пул считал бы его занятым навсегда.
local ok, result = pcall(c.execute, c, 'select id, name from customers where id = $1::int', id)

if not ok then
    p:drop(c)    -- в каком состоянии соединение, неизвестно: выбросить
    return nil, result
end

p:give(c)        -- вернуть

return result[1]
```

`take(timeout)` ждёт не дольше `timeout` секунд, по умолчанию —
`wait_timeout` пула. Отказ по сроку называет причину: `все 8 заняты`,
когда упёрлись в размер пула, и текст последнего отказа открытия, когда
место в пуле есть, а соединения нет, — это лечится на той стороне,
а не размером:

```text
соединение не получено за 5 с: все 8 заняты
соединение не получено за 5 с: открыть соединение не удалось: служба не отвечает
```

`give` и `drop` отвечают `true`, а на чужое соединение —
`false, 'соединение не из этого пула'`; второй `give` того же —
`false, 'соединение уже возвращено'`: одно соединение двумя записями
в пуле досталось бы двум файберам сразу. `drop` берёт и занятое,
и свободное.

### Настройки

Настройки проверяются целиком в `pool.new` и `pool.configure`, а не тогда,
когда до них дошло дело, и негодная — исключение: это ошибка того, кто
писал код, а не отказ службы. Незнакомый ключ — тоже исключение: опечатка
в имени иначе молча оставила бы умолчание, и пул вёл бы себя не так, как
написано. Отказ о незнакомом ключе и о роде значения показывает на строку
с `pool.new`; отказ о границе (отрицательный срок, нулевой `wait_timeout`)
— на строку внутри пакета, и что чинить, говорит только текст:

```lua
local ok, err = pcall(function()
    pool.new({ open = open, idle_timout = 60 })
end)

print(err)
-- app.lua:2: настройки пула: ключа «idle_timout» нет, есть alive, close,
-- idle_timeout, leak_timeout, max_lifetime, name, open, open_cooldown,
-- reset, size, sweep_interval, wait_timeout
```

| Настройка | Умолчание | Что значит |
|---|---|---|
| `open` | — | `open(left)` открывает соединение не дольше `left` секунд; отказ — `nil, причина` или исключение |
| `close` | нет | `close(conn)` закрывает соединение; его бросок пишется в журнал |
| `alive` | нет | `alive(conn)` — годно ли свободное соединение к выдаче; годно только `true` |
| `reset` | нет | `reset(conn)` — годно ли возвращённое к следующей выдаче; годно только `true` |
| `size` | 8 | сколько соединений держать; целое, не меньше 1 |
| `wait_timeout` | 5 | сколько ждать соединения; больше нуля |
| `idle_timeout` | 60 | сколько свободному позволено простаивать; 0 — сколько угодно |
| `max_lifetime` | 1800 | сколько соединению жить с открытия; 0 — сколько угодно |
| `open_cooldown` | 0,5 | первая пауза после отказа открытия; 0 — без паузы |
| `leak_timeout` | 300 | с какого удержания кричать об утечке; 0 — не кричать |
| `sweep_interval` | 5 | такт уборки; 0 — убирать только по `sweep()` |
| `name` | `pool` | имя пула в журнале, в `stats` и в имени фибера уборки |

`open`, `close`, `alive` и `reset` — функции либо таблицы с `__call`.
Сроки — числа не меньше нуля, без бесконечности и NaN: срок, равный
бесконечности, выглядит как «подождать подольше», а означает «не ждать
никого никогда».

Восемь соединений по умолчанию — потому что большой пул не ускоряет
работу, а переносит очередь со своего узла на чужой, где она уже никем
не ограничена и не видна. Пять секунд ожидания — потому что запрос,
которому не хватило соединения за пять секунд, упёрся не в пул,
а в перегруз, и честный отказ здесь полезнее очереди.

### Проверка живости: `alive`

`alive` зовётся перед каждой выдачей свободного соединения. Годным
считается только ответ `true`: соединение, для которого `alive` ответил
иначе или бросил ошибку, пул закрывает и берёт следующее свободное либо
открывает новое. Без `alive` годность свободного — только «не истёк
срок».

Срока у `alive` нет, поэтому она работает без сети. Сетевая проверка —
`ping()` у `pg` и `mysql` — удвоила бы число обращений к службе, а
на молчащем сервере не дала бы `take` уйти в свой срок: `ping()` ждёт
ответа без срока. Местная проверка видит только то, что клиент уже знает
сам: у `pg` — `active()` не бросил, у `mysql` — не бросил `quote('')`,
который экранирует на клиенте. Соединение, которое чужая сторона закрыла
молча, — перезапуск сервера, межсетевой экран, `pg_terminate_backend`, —
она пропустит: его обнаружит первый запрос, отказом, и `with` такое
соединение выбросит.

### Сброс перед возвратом: `reset`

`reset` зовётся на каждом `give` до того, как соединение ляжет
в свободные, — а значит, и в `with`, если тело не упало: упавшее тело
соединение теряет и без него. Годным считается только ответ `true`:
соединение, для которого `reset` ответил иначе или бросил ошибку, пул
закрывает, а `give` всё равно отвечает `true` — соединение взявший отдал.
В закрытом пуле `reset` не зовётся: соединение всё равно закроется.

Пул не знает, что такое транзакция, и `reset` — единственное место, где
её можно заметить. Кто открывает транзакции, обязан его задать и отвечать
в нём не `true`, пока транзакция открыта. Если клиент сам не говорит,
открыта ли она (у `mysql` — не говорит), её состояние ведёт тот, кто её
открывает: меткой на соединении, которую ставит `BEGIN` и снимает
`COMMIT` или `ROLLBACK`.

`reset` работает без сети. Срока у него нет, и `ROLLBACK` на молчащем
сервере не дал бы `give` вернуться вовсе. Откатить транзакцию — дело того,
кто её открыл, до возврата соединения; `reset` только не пускает в пул то,
что откатить не успели.

### Очередь

Когда все соединения заняты, просящий **ждёт на файберной условной
переменной**, а не крутит цикл: файбер снимается с потока и возвращается,
когда соединение освободится. Очередь честная — кто раньше встал, тот
раньше получит: пришедший, пока очередь не пуста, встаёт в её хвост, даже
если свободное соединение есть прямо сейчас.

Срок ожидания обязателен: `take(0)`, отрицательный и бесконечный срок —
исключение, как и такой же `wait_timeout`. Файбер, ждущий вечно, не ждёт
никого: он просто исчезает из виду, а запрос, который он обслуживал,
висит до срока на стороне клиента.

Ожидание, сорванное отменой файбера, пул не роняет: взявший уходит
с отказом `ожидание соединения прервано: …`, а очередь будит следующего.

Свободное соединение берётся последнее положенное, а не первое: так
работает малая часть пула, а лишние соединения простаивают и уходят
по `idle_timeout`.

### Срок входа

`open` получает аргументом остаток срока `take` — число секунд больше нуля —
и дольше не ждёт. У многих клиентов своего срока входа нет, и без этого
вход к молчащему серверу продлевал бы `take` на всё время, пока сервер
молчит.

Остаток посчитан по монотонным часам и никогда не больше срока `take`,
поэтому `clock.monotonic() + left` внутри `open` — это миг самого пула.
`open`, которая ждёт несколько раз (имя, рукопожатие, вход), отмечает этот
миг один раз и перед каждым ожиданием считает остаток заново: число `left`,
отданное целиком второму ожиданию, продлило бы вход на время первого.

Когда срок вышел, `open` не зовётся вовсе: нуля она не получает никогда —
у многих клиентов срок в ноль значит «ждать без срока».

Клиент, который срока не принимает вовсе, его и не соблюдает: рок `pg`
входит, пока сервер не ответит, и `connect_timeout` в строке соединения
у него не действует. Довести до такого клиента срок можно, только ожидая
вход в отдельном файбере.

### Отказ открытия

Соединение не открылось — просящий не получает отказ немедленно. Он ждёт
свой `wait_timeout`, а пул внутри этого срока пробует снова, увеличивая
паузу: 0,5 с, 1, 2, 4 и так до тридцати. Это поведение выбрано намеренно:
моргнувшая на полсекунды база не должна уронить все запросы разом.
Неудачный вход будит первого в очереди: место освободилось, и тот
пробует открыть сам, как только выйдет пауза, а не спит до своего срока.
Пауза меряется от отказа, а не от мига, когда взявший лёг спать: если
она вышла раньше — пока пул писал журнал или цикл событий стоял под
нагрузкой, — первый в очереди пробует сразу. Пауза в ноль
(`open_cooldown = 0`) значит «пробовать на следующей побудке»: без
передышки пул к лежащей службе не стучит.
Каждый отказ пишется в журнал записью `соединение не открылось` с полями
`pool`, `err` и `streak` — сколько отказов подряд.

Кому нужен быстрый отказ — `p:take(0.2)`.

`open` вправе и бросить: пул ловит исключение и считает его отказом
с тем же текстом. Отказом считается и соединение, которое уже лежит
в пуле: одно значение, отданное дважды, досталось бы двум взявшим.

#### Отказ, который время не лечит

Неверный пароль через полсекунды останется неверным, и ждать ради него
срок незачем. Об этом `open` говорит полем `retriable = false` у отказа —
у таблицы или у `box.error` с полезной нагрузкой.

```lua
local p = pool.new({
    open = function(left)
        local conn, err = client.connect({ host = host, timeout = left })

        if conn == nil and tostring(err):find('password authentication failed', 1, true) then
            return nil, box.error.new({ reason = tostring(err), retriable = false })
        end

        return conn, err
    end,
    close = function(c) c:close() end,
})

local c, err = p:take()

if c == nil then
    -- err — строка либо тот самый box.error; текст — tostring(err)
    return nil, tostring(err)
end
```

Такой отказ `take` отдаёт сразу и тем же значением, что вернула `open`, —
не строкой. Так же сразу его получают и остальные взявшие, пока в пуле нет
ни одного соединения: ждать им нечего, а службу, пока идёт пауза, пул
не спрашивает. Пока соединения есть, взявший ждёт своего срока, как
в полном пуле, — занятое могут вернуть, — и по сроку получает строку
с текстом отказа.

Пауза после окончательного отказа та же, что после любого: пароль,
который пробуют сотней файберов в секунду, — это сотня записей в журнале
безопасности службы. Когда пауза выйдет, службу спросят снова: пароль
могли и поправить. Отказ-строка, отказ без поля `retriable`
и с `retriable = true` остаются временными.

### Уборка: `sweep`, `idle_timeout`, `max_lifetime`, `leak_timeout`

Уборка закрывает свободные соединения, которые простояли дольше
`idle_timeout` или прожили с открытия дольше `max_lifetime`, и называет
в журнале удержанные дольше `leak_timeout`. Два срока считаются от разных
мигов: соединение, которое берут раз в секунду, не простаивает никогда,
но стареть не перестаёт.

Уборка идёт своим тактом — раз в `sweep_interval` секунд, фибером
`pool_<name>` на `tnt-loop`: пул, который убирает только тогда, когда
у него что-то просят, в тихий час не убирает ничего, а тихий час и есть
то время, ради которого заведён `idle_timeout`. Упавший такт не убивает
фибер: сбой уходит в журнал записью `уборка пула не удалась`. Истёкшее
соединение, до которого уборка ещё не дошла, не выдаётся: срок
проверяется и перед каждой выдачей.

`sweep()` открыт и наружу — убрать по своему поводу, например перед
снятием нагрузки, или в проверке без ожидания такта:

```lua
local p = pool.new({ open = open, close = close, idle_timeout = 60, sweep_interval = 0 })

local c = p:take()
p:give(c)

-- …прошла минута простоя…
p:sweep()   --> 1: сколько соединений закрыто
```

Утечку уборка не лечит, а называет: соединение не отнимается — его,
возможно, и правда держат. Запись `соединение держат дольше срока:
похоже на утечку` несёт `held` — сколько секунд держат — и `uses` — какая
это по счёту выдача соединения; об одном удержании она пишется один раз.

### Что показывает состояние: `stats`

```lua
local a = p:take()
local b = p:take()
p:give(b)

p:stats()
--> {
-->     name = 'pool', size = 8, closed = false,
-->     busy = 1, idle = 1, waiting = 0, total = 2,
-->     opened = 2, discarded = 0, open_failures = 0,
-->     takes = 2, gives = 1, drops = 0,
-->     waits = 0, wait_timeouts = 0, leaks = 0,
--> }
```

Показатели двух родов, и оба нужны. Мгновенные — `busy`, `idle`,
`waiting`, `total` (открыто и открывается прямо сейчас) — отвечают
на вопрос «хватает ли». Накопленные — открыто и закрыто за всё время,
отказов открытия, выдач, возвратов, выброшенных, ожиданий, истёкших
сроков, утечек — на вопрос «что тут было, пока никто не смотрел».

По ним видно то, чего не видно иначе: `waiting` больше нуля постоянно —
пул мал; `opened` растёт без остановки — соединения умирают
и переоткрываются; `open_failures` растёт — служба не отвечает. Пул,
у которого всё время ноль занятых, но тысяча переоткрытий, выглядит
здоровым только по мгновенным.

После первого отказа открытия появляется и `last_open_error` — текст
последнего отказа: `открыть соединение не удалось: служба не отвечает`.
Удачное открытие его не стирает: это след для того, кто смотрит,
а не состояние службы.

### Закрыть: `close`

```lua
p:close()       --> true
p:close()       --> false, 'пул уже закрыт'
p:is_closed()   --> true
p:take()        --> nil, 'пул закрыт'
```

Свободные соединения закрываются сразу, ждущие просыпаются и уходят
с отказом `пул закрыт`, такт уборки останавливается. Занятые
не отнимаются: файбер, работающий по соединению, получил бы обрыв
посреди запроса. Они закроются, когда их вернут.

### Общий пул процесса: `configure`, `default`, `status`, `reset`

Пул на процесс — это про одну службу, а не про все сразу: у базы
и у сокета очереди свои `open` и свои размеры, и жить им положено в двух
разных пулах, заведённых через `new`. Общий пул — для приложения,
у которого служба одна.

```lua
pool.configure({ open = open, close = close })   -- настройки проверены сразу
pool.status()    --> { configured = true, created = false }

local c = pool.default():take()                  -- пул заведён первым обращением
pool.default():give(c)
pool.status()    --> то же, что stats(), и configured = true, created = true

pool.reset()     -- закрыть общий пул и забыть настройки
```

`default` ленив: настройка идёт при подъёме узла, когда ходить к чужой
службе рано, а пул заводится при первом обращении. `default` без
`configure` — исключение `пул не настроен: позовите pool.configure до
pool.default`. Повторный `configure` закрывает прежний общий пул тут же:
ссылок на него больше нет, а сеансы на той стороне живы.

### Подмена в проверках: `_set_source`

Часы и условная переменная пула — внешние зависимости (`tnt-external`),
и проверка подменяет их, чтобы пятисекундный срок не стоил ей пяти
секунд:

```lua
local now = 100

pool._set_source({
    monotonic = function() return now end,
    cond = function()
        return {
            -- Ожидание без побудки двигает часы на весь срок и не спит.
            wait = function(_, seconds)
                now = now + seconds
                return false
            end,
            signal = function() end,
            broadcast = function() end,
        }
    end,
})

local p = pool.new({ open = function() return nil, 'служба не отвечает' end, sweep_interval = 0 })

p:take(5)
--> nil, 'соединение не получено за 5 с: открыть соединение не удалось: служба не отвечает'
-- четыре попытки за срок: в 100, 100,5, 101,5 и 103,5 — и ни секунды настоящего ожидания

pool._set_source(nil)   -- настоящие часы вернулись
```

Такт уборки меряется настоящими часами, а не подменёнными: подменённые
прыгают вперёд по воле проверки, и цикл, считающий по ним паузу,
закрутился бы вхолостую. Поэтому в проверках ставят
`sweep_interval = 0` и зовут `sweep()` сами.

### Что умеет

| Вызов | Что делает |
|---|---|
| `pool.new(opts)` | заводит пул; настройки проверены сразу, соединения не открыты |
| `:take(timeout)` | берёт соединение; ждёт не дольше `timeout`, по умолчанию `wait_timeout`; отказ — `nil, err` |
| `:give(conn)` | возвращает; `reset` решает, лечь ли ему в свободные |
| `:drop(conn)` | выбрасывает негодное: закрывает и забывает |
| `:with(fn, timeout)` | берёт, зовёт `fn(conn)`, возвращает в любом исходе; упавшее тело — `drop` |
| `:sweep()` | закрывает истёкшие свободные, называет утечки; отвечает числом закрытых |
| `:stats()` | мгновенные показатели и накопленные счётчики |
| `:close()` | закрывает пул; занятые закроются по возврату |
| `:is_closed()` | закрыт ли пул |
| `pool.configure(opts)` | настраивает общий пул процесса; прежний закрывается |
| `pool.default()` | общий пул; заводится при первом обращении |
| `pool.status()` | что с общим пулом, в том числе до того, как он заведён |
| `pool.reset()` | закрывает общий пул и забывает настройки |
| `pool._set_source(s)` | подменяет часы и условную переменную в проверках; `nil` — настоящие |

## Что пулить не надо: `net.box`

`net.box` мультиплексирован: одно соединение обслуживает сколько угодно
одновременных запросов, на сервере каждый идёт в своём файбере, а ответы
находят своих по номеру запроса. Проверено на 3.8: десять `conn:call`
функции с `fiber.sleep(0.5)` из десяти файберов на одном соединении —
0,50 с, а не 5; ответы не перепутаны; так же `eval` и `is_async`.

Предел одновременных запросов есть, но стоит он на стороне сервера —
`iproto.net_msg_max`, 768 по умолчанию, — и общий на все соединения:
сорок вызовов при `net_msg_max = 16` идут три волны, 1,5 с, что через
одно соединение, что через четыре. Пул соединений `net.box` не прибавил
бы ни параллельности, ни пропускной способности — только сессии на узле
и загрузку схемы на каждое соединение. Одно соединение на узел и есть
правильное число, и это не упрощение, которое можно «доделать пулом».

## Чем пришлось поступиться

**`with` при ошибке в теле соединение выбрасывает, а не возвращает.**
Пул не умеет отличить оборванную сеть от незакрытой транзакции, а отдать
соединение в непонятном состоянии следующему — значит подарить ему чужую
незавершённую работу. Цена — новый вход после каждой ошибки, даже той,
что соединению не повредила. Кому она дорога, зовёт `take`, `give`
и `drop` сам.

**Отказ тела (`return nil, err`) соединение возвращает — и открытую
транзакцию вместе с ним.** Отказ от поломки отличается: «нет такой
записи» не повод платить за новое соединение. Но тело, отказавшее
между `BEGIN` и `COMMIT`, отдаёт следующему взявшему соединение
в транзакции, и тот зафиксирует чужую работу вместе со своей. Пул этого
не видит. Кто открывает транзакции, задаёт `reset`, который отвечает
не `true`, пока транзакция открыта (`not c:active()` у `pg`), — такое
соединение пул закроет. Ручной `give` — то же самое.

**Окончательный отказ приходит не строкой.** `take` и `with` отдают
его тем значением, что вернула `open`, и строковые методы на нём
падают: текст берут через `tostring(err)`. Таблице нужен `__tostring` —
без него в журнал и в `last_open_error` попадёт адрес таблицы, а не
текст. Строкой его не сделать: тот, кто его собрал, знает о нём больше,
чем пул уместил бы в строку.

**Живость и сброс — без сети и без срока.** Соединение, закрытое чужой
стороной молча, местная проверка не видит: его обнаружит запрос, которому
оно досталось, — отказом. Сетевая проверка удвоила бы обращения к службе,
а на молчащем сервере не дала бы `take` уйти в свой срок, а `give` —
вернуться вовсе.

**`max_lifetime` (полчаса) обязан быть короче самого короткого чужого
предела** — своего у базы, у балансировщика и у межсетевого экрана.
Тогда пул переоткрывает соединение сам, в спокойную минуту, а не узнаёт
об обрыве в середине запроса.

**Занятые соединения `close()` не отнимает** — они закрываются, когда
их вернут. Файбер, не вернувший соединение, держит его до конца жизни
узла; `leak_timeout` о таком только пишет в журнал.

**Срок `take` меряется настоящими монотонными часами, а ожидание
отсчитывает его от отметки цикла событий.** После работы без уступки
ожидание кончается раньше на её время; срок перепроверяется после
каждого пробуждения, и недоспанное доспится следующим оборотом, так что
отказа по сроку раньше срока не бывает. Ожидание внутри `open`,
отсчитанное от отметки цикла, тоже может кончиться раньше `left`,
но не позже.

**`sweep_interval > 0` заводит фибер на пул.** Незакрытый пул —
незакрытый фибер; в проверках ставьте 0.

**Граница настройки показывает на строку пакета.** Незнакомый ключ
и неверный род значения названы на строке вызывающего, а отрицательный
срок, нулевой `wait_timeout` или `take(0)` — на строке внутри пакета:
граница проверяется и у срока, пришедшего с `take`, где описания
настроек нет. Что чинить, говорит текст.

**Пароли пул не видит.** Вход заперт внутри `open`, и это осознанно:
единственное, что приходит наружу, — текст отказа открытия, и он
попадает в журнал и в `last_open_error`. Не возвращайте из `open` строку
с адресом базы и паролем внутри. У `pg` такая строка получается и сама:
пароль с кавычкой, отданный ключом `password`, ломает разбор строки
соединения, и обрывок пароля попадает в текст отказа, — поэтому пример
собирает строку соединения с экранированием.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.
Пул берётся из исходников, зависимости — установленными.

Часы и условная переменная в проверках пула подменены двойником, который
двигает часы на весь запрошенный срок ожидания: сроки, паузы после отказа,
простой и время жизни проверяются точно и мгновенно. Очередь ожидающих
проверяется на переменных, которые считают побудки, — видно, кого будят,
а не только что кого-то будят. Одновременность — несколько файберов
берут и возвращают разом, открытие отдаёт управление, закрытие идёт
посреди ожидания — проверяется на настоящих файберах и настоящем времени
с короткими сроками. Отказы настроек сверяются с текстом дословно, записи
журнала — ловушкой `tnt-log`.

Покрытие строк — 100 %, убитых мутантов — 100 % (139 проверок,
418 мутантов в четырёх модулях).
